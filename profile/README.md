## What is Ghost Buster Pro?

Ghost Buster Pro is a small utility for macOS from an independent developer who publishes a range of focused Mac tools. It scans for files belonging to applications that are no longer installed.

## A different question from what cleaners ask

The distinction matters when deciding whether you need it alongside anything else you own. General cleaning tools ask which files are disposable — caches, logs, temporary data belonging to software you still use.

This asks a narrower and more definite question: which files belong to software that is gone? A cache from an application you use daily will be rebuilt tomorrow. A support folder from a program you deleted in 2023 will sit there until something removes it. The second category never regenerates, which makes recovering it permanent rather than temporary.

## It scans the moment it opens

There is no setup, no configuration and no wizard — the developer says so outright, and it is accurate. Launching it starts the scan.

What comes back is a total figure for recoverable space, a chart showing which departed applications left the most behind, and a size bar on every individual item so you can see what each one weighs rather than only the sum. Results sort by size or by name, and a footer counts what you have selected.

## Nothing is deleted without you choosing it

There is no automatic cleaning mode, and this is deliberate rather than a missing feature. Every item is selected by hand.

You choose whether removal goes to the Trash, where it can be retrieved, or bypasses it permanently. Folders can be added to an ignore list so they never appear in future scans — useful for the leftovers you keep intentionally, such as licence files for software you plan to reinstall.

## Two limits worth knowing

First, the system requirement is unusually high and the developer raises it regularly, so an older Mac may find itself unable to install or update.

Second, it comes from the Mac App Store, which means it runs sandboxed. It asks for access to your user folder, and leftovers sitting in system-level locations may be outside what it can see. The developer does not publish the exact scope of the scan, so treat it as thorough within your own folder rather than exhaustive across the whole disk.
